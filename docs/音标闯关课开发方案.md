# 音标闯关课 · 开发方案(定稿)

> 目标一句话:**让零基础、甚至"怎么教都不会"的小学生,不靠家长老师,自己把 48 个国际音标学到"看音标能读出生词"。**
> 方法论:直接教学法(Direct Instruction)+ 无错学习(errorless learning)+ 掌握制过关 + 滚动复习。
> 本文档是施工蓝图:下次开发音标模块,按此文档执行,不再重新设计。
> 定稿时间:2026-08-04。配套决策已由用户拍板:音源用 AI 生成一次存静态资产;形象图走 hueling;唯一人工环节是十分钟试听验收。

## 1. 为什么现在教不会(问题定义)

现状 = 教师上传讲解视频(`phonetic_videos` 表)+ 学生端 PhoneticsHub 看视频。看视频是被动输入,没有练习、没有检测、没有间隔,而且**根因**是:中国孩子的耳朵里没有 /ɪ/-/iː/、/e/-/æ/、/θ/-/s/、/v/-/w/ 这些对立,**听不出的音,符号教一百遍也绑不上**。所以顺序必须是:先练耳朵 → 再绑符号 → 再拼读应用。视频降级为每课的选修资料(按 `phonetic_symbol` 字段挂进对应课)。

## 2. 教学法内核(六铁律)

1. **一天一个新音**(快车道日两个),5-10 分钟一课,48 音摊约 8 周。
2. **易混音隔周教**:/ɪ/ 与 /iː/、/e/ 与 /æ/ 等绝不同周出现;先各自练到自动化,再上专门"对比课"。
3. **无错设计**:练习干扰项**只从该生已掌握的音里选**,永不拿没学过的音当选项;新题型先用简单内容教玩法,新内容只放进熟玩法。
4. **纠错是剧本不是打叉**:答错 → 立刻示范正确答案(高亮+重放音频+口型要点)→ 隔 1-2 题原题重考 → 课末再考 → 次日复习必含。连错 2 次直接亮答案让孩子点(无错兜底),该题记为未掌握。
5. **掌握制过关**:当堂混合小考 ≥90% 才点亮;不过关次日**换题重教**(题目由规则引擎重新生成,防背答案)。已点亮的音进入滚动复习,永不毕业。
6. **学一个用一个**:每学会一个元音,当天就用已掌握的辅音拼真词(学 /æ/ 当天拼出 cat、bag),每课以"你自己读出了一个新词"收尾。

## 3. 单音课"七步剧本"(交互规格)

全程**无文字指令**(指令用图标+固定引导音效),不用打字,单手可完成。每步的数据都落 `phonetic_attempts`(见 §7)。

| 步 | 名称 | 交互规格 | 判定与出口 |
|---|---|---|---|
| ① | 形象登场 | 角色图入场动画(framer-motion,尊重 prefers-reduced-motion)→ 自动播孤立音 ×3(间隔 800ms)→ 口型要点一行字+角色口型图 → 「想看老师讲」按钮挂对应 `phonetic_videos`(有则显示,选修) | 无判定,点大按钮进下一步 |
| ② | 耳朵关 | 「听到它就点角色」:连播 6 个音(孤立音变体),含目标音 3 次、对照音 3 次。对照音**从远到近**:第 1-2 题用差异极大的已学音,第 3 题起用较近的音(但**不用**未学的易混对) | 6 题 ≥5 对进③;否则重放示范后再来 6 题(换顺序);第二轮仍不过也放行进③(不卡死),标记 weak_ear |
| ③ | 符号绑定 | A 型:出符号卡,点 2-3 个喇叭找它的音;B 型:播音,点 2-4 张符号卡(干扰符号只用已掌握的)。共 6 题 A/B 混排 | 记对错,走纠错剧本;全部完成进④ |
| ④ | 跟读 | 大符号+角色,播音后录音(复用 `useAudioRecorder`);先走讯飞 ISE,未配置则 Whisper,都不可用则只回放自比。**任何评分都不拦路**,只给笑脸/加油脸 | 完成即过(录了就行) |
| ⑤ | 词中找音 | 3 题:播真词读音+显示拼写(词优先取自本机构可见词书、该生已学词,见 §8 选词查询),问「里面有没有它?」(有/无二选)或「它在头/中/尾?」(三选,仅辅音用) | 记对错,走纠错剧本 |
| ⑥ | 拼读起飞 | 音珠游戏:2-3 颗音珠(全部为已掌握音+今日音),孩子按顺序点/拖,珠子相撞合成单词并整词发音。最后一题给一个**没学过的新词**的音标串,孩子拼完点「我读出来了!」→ 揭示单词+释义 | 元音日必做;辅音日若凑不出真词(前两周),用"音珠连读"代替(只合成音不成词) |
| ⑦ | 混合小考 | 8 题:今日音 3 题 + 已掌握音随机 5 题,题型从 ②③⑤ 池里抽 | ≥7/8(约 90%)→ 点亮+徽章动画;5-6 → 明日重教(换题);<5 → 明日从②重走 |

**每日会话结构**:进入音标课 = 滚动复习(3-5 分钟,到期音各 2 题,三档间隔 1/3/7 天)→ 今日新音七步 → 结束页(地图点亮+「今天你能读 N 个词了」累计数)。复习优先,新课其次,总时长目标 ≤12 分钟,硬上限 15 分钟(到点直接收尾结算)。

## 5. 八周编排 + 对比课

每周 5 个学习日。快车道日可排 2 音。顺序原则:先易后难、易混隔周、元音日=拼读收获日。

| 周 | 新音(按日) | 对比课(周五加餐) |
|---|---|---|
| W1 | m+p / b+t / d+k / ɡ+s / l(共 9,教玩法) | 无(第一周只建立机制) |
| W2 | æ / ɒ / ɪ / e / ʌ(首批短元音,每天当日拼 CVC 词) | p-b(清浊初体验) |
| W3 | f / h / w / n / uu(uː) | t-d |
| W4 | aa(ɑː) / oo(ɔː) / ii(iː) / schwa(ə) / v | k-ɡ、**w-v** |
| W5 | ei / ai / oi / er(ɜː) / s-z 复推+z | **ɪ-iː**(隔了 3 周,可以对比了) |
| W6 | ou / au / u(ʊ) / sh / ch | **e-æ**、ɒ-ɔː |
| W7 | th(θ) / dh(ð) / r / dg / ng | **θ-s**、**l-r**、ʊ-uː |
| W8 | ia / ea / ua / zh / tr+dr / ts+dz | n-ŋ、ʃ-tʃ、**毕业考** |

**对比课**(单独课型):最小对立对听辨 10 题(ship/sheep 式:播一个词,点对应词/图),前 3 题音频用**夸张拉开**的变体,逐题回归正常语速(知觉渐减法)。数据写入 `phonetic_confusions`。
**毕业考**:10 个没学过的词,只给音标,孩子拼读后选出对应单词(四选一),≥8 过,发"解码员"大徽章。
**入学摸底**(首次进入,2 分钟):符号绑定 B 型抽测 12 题(覆盖各周代表音),连对判掌握直接点亮(仍进复习池);摸底可跳过(=从零开始)。

## 6. 资产生产管线(一次性,产物入库永久复用)

### 6.1 音频

- 脚本:`backend/scripts/gen_phoneme_audio.py`(一次性,参照 `gen_pet_midforms.py` 的脚本风格)。依赖:`edge-tts`(已有)、`pydub`(新增 dev 依赖,不进生产 requirements)、ffmpeg(本机已有)。**注意清空代理环境变量再跑**(SOCKS 代理坑,见 §12)。
- 每音 3 变体:`iso`(孤立音)、`long`(拖长/重复两遍)、`inword`(「/æ/ … /æ/ … cat」三段拼接:孤立音×2+例词)。
- 切割规则:
  - 直出类:整段保留,首尾静音裁剪(pydub `detect_leading_silence`)。
  - 载体切元音(V+塞音词如 "at"):找元音后的**闭塞静默谷**(能量骤降点),切谷前,尾部 10ms 淡出。
  - 载体切辅音头(C+V 词如 "sea"):摩擦音/鼻音保留起始段至**浊化拐点**(能量+过零率跳变);爆破音保留爆破 burst+60~90ms。
  - 载体切尾(如 "song" 的 ŋ、"cats" 的 ts):从末元音能量谷切到结尾。
  - 全部输出:mp3 48kbps mono,响度归一(pydub `apply_gain` 对齐 -20dBFS),首尾 10ms 淡入淡出。
- 命名与存放:`frontend/public/phoneme-audio/{key}.{variant}.v1.mp3`(**改内容必须升 v 号**——nginx 对静态资源发 `immutable`,吃过封面图的亏);随 dist 部署,总体积约 2-3MB。脚本同时产 `manifest.json`(key→文件→时长→生成策略),验收页和前端都读它。
- **验收页(必做)**:管理端路由 `/admin/phoneme-qa`(仅 admin),48 音 ×3 变体一屏列出,逐个点播,每条可标 ❌+备注,导出不合格清单 JSON。不合格的音:换载体词重切 → 仍不行 → 启用 Azure SSML 兜底(§0)→ 再验。**全绿才允许开发课程引擎接入音频**。AI 没有耳朵,这一步必须人来,预算十分钟。

### 6.2 形象图

- 脚本:`backend/scripts/gen_phoneme_chars.py`,走 `image_service.py` 同款 hueling 调用(返回 b64_json 直接存盘,别当 URL)。
- Prompt 模板(统一画风,一次定稿):`children's picture book style, flat colors, warm palette (orange #FF6B35 / yellow #FFD23F), cute {角色}, the IPA symbol "{符号}" integrated into the design, white background, no text other than the symbol`。**背景要白底后本地 flood-fill 抠透明**(直接要 transparent 会触发上游 500,见 §12)。
- 每音生成 3 张人工挑 1 张 → `frontend/public/phoneme-chars/{key}.v1.webp`(webp 压缩,单张 <40KB)。

## 7. 数据模型(加入 `database_schema.sql` + `core/database.py` 幂等建表)

```sql
-- 音标掌握进度(⚠ 必须带 UNIQUE,吃过 word_mastery 缺唯一约束导致永久 500 的亏)
CREATE TABLE IF NOT EXISTS phonetic_progress (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  symbol_key VARCHAR(16) NOT NULL,          -- §4 的 key
  status VARCHAR(12) NOT NULL DEFAULT 'new',-- new/learning/mastered
  attempts INTEGER NOT NULL DEFAULT 0,
  correct INTEGER NOT NULL DEFAULT 0,
  weak_ear BOOLEAN NOT NULL DEFAULT 0,      -- 耳朵关两轮未过的标记
  review_stage INTEGER NOT NULL DEFAULT 0,  -- 0/1/2 → 间隔 1/3/7 天
  next_review_date DATE,
  mastered_at DATETIME,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(user_id, symbol_key)
);
CREATE INDEX IF NOT EXISTS idx_phonprog_user ON phonetic_progress(user_id, next_review_date);

-- 易混矩阵:答错时"选了谁"逐对累计,喂对比课推送和教师热力图
CREATE TABLE IF NOT EXISTS phonetic_confusions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  symbol_key VARCHAR(16) NOT NULL,
  confused_with VARCHAR(16) NOT NULL,
  count INTEGER NOT NULL DEFAULT 0,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(user_id, symbol_key, confused_with)
);
```

课程目录(48 音数据、周编排、题型规则)**不进数据库**,做成常量 `backend/app/services/phonetic_course.py::PHONETIC_CATALOG`——固定教学大纲,进 DB 只会引来无意义的管理界面需求。逐题明细不单独建表(量大价值低),七步各步的通过情况聚合进 `phonetic_progress` 计数即可。

## 8. 后端设计

新文件 `backend/app/services/phonetic_course.py`:
- `PHONETIC_CATALOG`:§4 全量数据(dataclass 列表)。
- `tokenize_ipa(s)`:把 `words.phonetic` 拆成音素序列。**直接移植 `frontend/src/components/ColoredPhonetic.tsx` 的逻辑**(多字符音素表按长度优先匹配),外加归一化表:`ɡ→g, ɹ→r, ʧ→tʃ, ʤ→dʒ, ɛ→e, oʊ→əʊ, ɚ→ə, ɝ→ɜː`,剥 `ˈ ˌ / [ ] ( )`。tr/dr/ts/dz 按相邻 token 对判定。
- `words_with_sound(db, user, key, limit)`:选词查询。**多租户红线**:words 不是锚点表,必须显式 join `book_words`+`word_books` 且 `word_books.org_id IS NULL OR org_id = user.org_id`(聚合不经锚点模型被过滤器罩不住,已有两次泄漏教训);排序:该生已学(join user_word_progress)优先 → difficulty 升序 → 词长升序。结果按 key 进程内缓存 10 分钟(词库低频变动)。
- `build_lesson(user, key, mastered_keys)`:按 §3 生成七步题目(含正确答案下发,客户端判题;音标练习无金币无排名,可接受,提交仅更新进度且服务端做计数上限防刷)。
- `build_review(user, due_keys)` / `build_placement()` / `build_contrast(pair)` 同理。

端点(挂进现有 `api/v1/phonetics.py`,前缀 `/api/v1/phonetics`,`get_current_user`):
- `GET /course` → 地图:每音 {key, status, review_due, week, lane} + 累计可读词数。
- `GET /lesson/today` → {review: [...], new_sound: 七步剧本 | null, contrast: 对比课 | null}(服务端按进度决定今天上什么)。
- `POST /lesson/result` → body {symbol_key, step_results, quiz_correct, quiz_total, confusions:[{key, confused_with}]};服务端算过关/重教、更新 review_stage 与 next_review_date。**幂等**:带客户端生成的 attempt_id,重复提交不重复计数(沿用 claim 思路)。
- `GET/POST /placement` → 摸底 12 题/交卷点亮。
- `GET /api/v1/teacher/phonetics/heatmap?class_id=` → 班级 × 48 音掌握矩阵 + 全班 top 易混对(挂进现有 teacher/phonetics.py,org 隔离随 user 链)。

## 12. 红线与坑(本仓库血泪,施工前重读)

1. **TTS 单声音**:英文音全部同源 en-GB-SoniaNeural(静态音素文件也是它生成);失败保持安静,**禁止 speechSynthesis 兜底**。
2. **静态资产缓存**:public 下固定文件名 + nginx immutable → 换内容必须升文件名版本号(v1→v2),否则老用户一个月看旧资产。
3. **UNIQUE 约束**:进度/易混表必须带唯一约束上线(word_mastery 缺约束曾致并发重复行永久 500)。
4. **多租户**:选词查询显式 join word_books 并按 org 过滤;不经锚点模型的聚合,tenancy 过滤器罩不住。
5. **hueling 出图**:要白底再本地抠图(transparent 触发上游 500);返回的是 b64_json;跑脚本前清代理环境变量(SOCKS 会崩 httpx)。
6. **部署**:前端随整份 dist(哈希级联,不可单文件替换;部署前验 version.json 与 bundle 构建号自洽);后端新文件 scp 无妨,但改动**已存在**的生产文件(phonetics.py/main.py)前先 md5 对比,漂移则用远程锚点 patch(classes.py/main.py 有先例)。
7. **API 路径**禁止以 `/admins` 结尾(Safari 内容拦截器会掐请求)。
8. 音频/图片是平台级公共资产,放 `frontend/public/`,**不放 UPLOAD_DIR**(该目录整体无鉴权公开,只准放公开图,且这里根本不该依赖它)。
9. 幂等提交:result 端点带 attempt_id 去重(参照 claim_client_batch 思路),弱网学生场景必踩重复提交。
